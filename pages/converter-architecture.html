The converter reads every format into one model of the map and writes every format from it. This page shows how it is built today and the architecture suggested for it. The format details are on the description page.

Today

holds layout logic (edge routing, small position corrections) the model every route passes through

There is no layout algorithm: no route places nodes. Every route keeps the positions of the input map and only corrects them by a few pixels. What the converter calls a layout is the routing of the arcs and these corrections, and they sit in four places.

WhereWhat it does
celldesigner.write, lines 318–540Straightens main lines (up to 10 px), moves a main line onto a node's centre, aligns modifiers with their square (up to 15 px), makes room for a complex's name, places the square and its bends, routes the modifier arcs.
celldesigner.read, straightReads the straight or the advanced geometry. straight() puts each process midway, used only from CellDesigner to SBGN-ML.
sbgnml.pyFits compartments for Newt (shifted, placed, for_newt, moved), its own straight and advanced arcs, bend simplification from cd_bends.
style.standardiseStandard node sizes and rescaling, GraphML output only.

From one GraphML map the two straight files differ. CellDesigner (straight) gets the square midway, straightened main lines and aligned modifiers. SBGN-ML (straight) keeps yEd's process positions and runs the arcs from centre to centre.

Suggested architecture

The same rows, with two new columns between the model and the writers. Layout moves out of the readers and writers into one module. What only one target needs (CellDesigner, Newt, yEd) goes into an adapter next to its writer. Readers then read and writers write, nothing else.

layout, in one place the model, as today

What changes

  • Readers read what the file says, the CellDesigner reader too. Straight or advanced is chosen in the layout, not when the file is read.
  • Reactions: the main reactant and product of each process are worked out once, on the model. Today celldesigner.write, celldesigner.straight, sbgnml.write and rules.py each work them out on their own.
  • Layout: straight and advanced become two lists of passes, the same for every format. Both straight files from one map then have the same geometry. Placing the nodes of a map that has no coordinates (SBML without a layout) would be one more pass.
  • Adapters hold what one target needs: CellDesigner's anchor points, multimer front shape and MINERVA's square anchors, Newt's compartment padding, yEd's standard sizes.
  • Report: the converter's messages, about 30 kinds (left out, moved, not converted) go into one list. Today they are printed and caught by the page.
  • Routes: which input gives which buttons moves from the script in converter.html into the converter, so the page and the command line run the same code.

Order of work

  1. Convert every Atlas map and every official CellDesigner file with the current code and keep the results as reference files.
  2. Report and routes. Nothing in the files changes.
  3. Reactions on the model, then the layout passes moved out of celldesigner.write one at a time, each checked against the reference files.
  4. The adapters, then SBGN-ML (straight) on the same passes. This is the one intended change in the files.
