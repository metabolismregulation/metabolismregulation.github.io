The converter converts maps: every input has a drawing. It reads every format into one model of the map and writes every format from it. The model holds two things: the biology (entities, reactions, annotation) and its drawing (boxes, arcs and bends, each pointing to what it draws by its id). Readers read and writers write, nothing else. What every format shares in the layout is in one module, what only one target needs (yEd, CellDesigner, Newt) in an adapter next to its writer. SBML with layout is planned in both directions, SBML without layout and BioPAX as an export only (dashed). The format details are on the description page.

How it is built

layout, in one place the model: biology and drawing planned

Layout

There is no layout algorithm: no route places nodes. Every route keeps the positions of the input map and corrects them by a few pixels at most. The layout is the routing of the arcs and these corrections.

ModuleWhat it does
layout.pyFor every format: the main reactant and product of each process, the bends that matter (the long L, bends that move a line by more than 20 px), two processes on the same species kept apart, an arc's route without the process ports, and the straight layout of a map read from CellDesigner (arcs at the centres, metabolites at the yEd size).
cd_layout.pyCellDesigner: the boxes as it draws them (metabolite circles, multimers, room for a complex's name), the process square, anchors and edit points, and the small moves that make lines meet straight (main lines up to 10 px, an end onto a larger node's centre line, a modifier up to 15 px onto its square). The moves are listed under the map and can be switched off on the Converter page (Move nodes slightly to straighten lines).
newt_layout.pyNewt: every process and gate in a compartment, each compartment as large as Newt's margin needs, neighbours too close for it moved apart.
style.pyyEd: standard node sizes and rescaling, when the box is ticked.

Why biology and drawing apart

Most formats already keep them apart. CellDesigner has species and their aliases (one species can be drawn more than once). The SBML Layout package draws species and reactions with glyphs that refer to them by id. BioPAX has no drawing at all. v1's model had only the drawing: one node per alias, joined again by label when CellDesigner was written, so a species drawn twice came back as two species. Now the CellDesigner reader keeps each alias's species, and for yEd and SBGN-ML, which hold only a drawing, the biology is built from it, joining the nodes of one entity by their annotation (HGNC, UniProt, ChEBI), or by their label where a map has none. The biology alone is also what an export to BioPAX or to SBML without layout writes.

Maps only

Every route starts from a map. SBML with layout converts both ways, as it carries a drawing. SBML without layout and BioPAX are written from a map but not read: making a map from a file without a drawing (BioPAX, SBML without layout, a table) is the work of the human-like layout project, not of the converter. Its maps can then come here.

Order of work

In a new repository map-converter, started from a copy of v1 with its history. v1 is kept, unchanged, as map-converter-v1, the reference. A branch v1-fixed holds v1 with bug fixes only, the fallback if the page has to go back to it.

  1. Done. Every Atlas map, every official CellDesigner and SBGN-ML file and the test files converted with v1 and kept as reference files.
  2. Done. The model (biology and drawing), the readers and writers adapted to it.
  3. Done. Report and routes.
  4. Done. The layout out of the readers and writers into layout.py and the three adapters, checked against the reference files after each move.
  5. SBML with layout, read and written, and SBML without layout written. Later.
  6. BioPAX written. Later.
