Converter

The converter turns a map from one format into another. It does not hold a map strictly to the standards. Common deviations are accepted where their meaning is clear, so that the conversion is as useful as possible, and whatever is left out is listed. It runs in the browser, and the files never leave the computer. The annotation (HGNC, UniProt, ChEBI) is converted with the map. In GraphML it is read from the node properties, or from the node links when a map has none.

Each section below has the same parts: Input (format, version, file extensions), Check (what is checked before conversion), Output (one row per download button) and Not converted (what is left out). Each file is named after the input file and its button, for example glycolysis-straight.xml for CellDesigner (straight line) from glycolysis.graphml, and glycolysis.xml for CellDesigner.

Layouts: the files without a variant keep the layout of the input map as closely as possible: node positions, process ports and the key bends. Straight line is the simpler fallback, for a map whose drawing does not convert well: every arc a straight line between node centres, for laying out by hand. In CellDesigner each process glyph sits midway between its main reactant and product. In CellDesigner a few nodes move a little so that lines meet straight. Straight & bends and as drawn keep every node in place (CellDesigner drawing). The three CellDesigner fallbacks (straight line, straight & bends, as drawn) are made only when ticked under "Additional CellDesigner layouts". Ticking or unticking a box, this one or Standard node sizes, converts the maps already on the page again. SBGN-ML comes adjusted for Newt, the recommended file for now, and plain, with the compartments as drawn (SBGN-ML and SBGN-ML for Newt), each also in straight line.

From GraphML

Input: yEd GraphML (.graphml), an SBGN Process Description map.

Check: the SBGN Process Description rules, with two exceptions: 1) a phenotype may also stand for a perturbing agent or a submap (the palette's submap glyph is read as a phenotype), and 2) stimulation, inhibition, modulation and trigger may connect two entities directly (CellDesigner’s Reduced Notation). Elements that break the rules are left out of the converted files.

CellDesigner 4.0 is SBML Level 2 Version 4 with the CellDesigner extension. A molecule drawn more than once is one CellDesigner species with one alias per drawing, as CellDesigner saves it. Two boxes are the same species when they have the same identifier (HGNC, UniProt or ChEBI, else the label), state, compartment and glyph. All SBGN-ML files have their colours in the SBML render extension and the annotation as RDF in each glyph. An arc leaving a phenotype is left out of them, the phenotype and the arcs into it kept: an SBGN phenotype takes no outgoing arc, and the converter does not decide whether it is a perturbing agent or a submap.

SBGN-ML and SBGN-ML for Newt: the plain SBGN-ML files keep the compartments as drawn. Newt leaves a margin inside a compartment and otherwise redraws it around its contents, so compartments that touch or stand close in the map overlap there. In the files for Newt every process and logic gate sits in a compartment, and each compartment is as large as that margin needs. Edges aligned in the map stay aligned. Where two compartments' contents are too close for the margin, everything past their shared edge moves on by the missing distance, noted under the map. A node outside every compartment that a compartment grows over by more than half is covered whole, so no edge runs through it. Newt also aims every arc at the centre of its node, so an arc that leaves a node off centre gets a bend just outside it, to keep its course.

Not converted: the elements that break the rules, listed under the map in red, one per line with the element's id, label (an arc by its ends) and reason. Arcs leaving a phenotype, left out of the SBGN-ML, are listed under the map with the phenotype's id and label. Equivalence operators are left out of the CellDesigner files, which have no such element, and kept in the SBGN-ML.

The SBGN-ML files are made from the CellDesigner file directly, with their colours in the SBML render extension and the annotation as RDF in each glyph. An arc leaving a phenotype is left out, the phenotype kept, and the files for Newt are adjusted as from GraphML.

CellDesigner draws its nodes over the arcs, so its files hold bends nobody sees: inside an arc's own start or end node, or on the straight line between two others. These are left out of the GraphML and SBGN-ML files, and an arc starts where its line crosses the node's border in CellDesigner.

All SBGN-ML files give a homodimer its N:x unit, N:2 included. Since CellDesigner files carry no site names, their state variables have none.

Not converted: text and shapes drawn on layers, groups, compartments drawn as an edge line, and state variables on a complex, listed under the map.

From SBGN-ML

Input: SBGN-ML 0.3 or SBGN-ML 0.2 (.sbgn), Process Description. Also a Newt file (.nwt): SBGN-ML with Newt's own settings added, converted the same way. A file saved by Newt is read as it is: what Newt moved stays moved. An Activity Flow map is read too and drawn the CellDesigner way: each activity as the entity it comes from, a protein's activity as a protein, the influences as arcs between them. In a map that mixes Process Description and Activity Flow, an activity joined to its entity by a performance arc is drawn as that entity, one node for the molecule and its activity, as in CellDesigner's reduced notation. "activity" at the end of an activity's name is dropped, so "SHC activity" becomes SHC.

Check: none.

The CellDesigner files are converted from the SBGN-ML, not from the GraphML. CellDesigner has no logic gate feeding another gate. When the second gate is OR, it is dropped and each of its inputs points at its target with the same arc, as several arcs onto one target read as any of them. When it is AND, the arc is left out.

Not converted: glyph and arc classes the converter does not read, and clone markers, left out of all three files and listed under the map with their class and ids. A perturbing agent becomes a phenotype in all three files. CellDesigner, like the maps of this site, has one glyph for both. An Activity Flow delay is kept in the GraphML as a logic operator labelled τ. The CellDesigner files have no delay, so there its input is joined to its target. An Activity Flow submap becomes a phenotype with its name, without its terminals and tags. Its equivalence arcs become plain lines to that phenotype in the GraphML. Equivalence operators are left out of the CellDesigner files, which have no such element, and kept in the GraphML.

Standard node sizes

Purpose: for maps drawn with a font that is too large or too small for their shapes, so the shapes do not look as they should, for example rounded corners that cannot be told from sharp ones, or arrowheads too small to see.

Applies to: a second GraphML file, "GraphML standard sizes". With the box ticked, every map gets it, so that its nodes look alike.

Without the box: a map from CellDesigner or SBGN-ML gets the file only when it is drawn at a clearly different scale, when one of these is more than 20% off (a GraphML map gets it only with the box ticked):

  • the median protein height, against the standard 40,
  • the median font size of the names, against the program's default, 12 in CellDesigner and 11 in Newt,
  • on a map without proteins, the median metabolite height, against the usual 25 to 40.

Sizes: proteins 80 x 40, metabolites 40 x 40 circles, names in font size 14. The map is rescaled if its proteins are much larger or smaller.

CellDesigner drawing

Small moves: CellDesigner draws a reaction from the centre of a node or one of its fixed connection points, and puts the process glyph midway on its line. In CellDesigner a few nodes move a little so that lines meet straight: a main line up to 10 px off the horizontal or vertical is straightened, an end that meets a larger node beside its centre moves onto that node's centre line, and a modifier up to 15 px off its process glyph moves onto it. Each move is listed under the map with the node and the distance. The other CellDesigner files move no node: straight line, straight & bends (the drawing of CellDesigner without the moves) and as drawn.

As drawn: CellDesigner (as drawn), for going back and forth between editors, keeps every node where the input map has it. A process glyph more than 3 px from midway is held where the input map has it by two edit points on the line, and a line that the input map draws level into a large node beside its centre gets one edit point just outside that node. Every added edit point lies at least 3 px outside the nodes, as CellDesigner draws lines over nodes. They are left out when the file is converted back. They make the file harder to edit in CellDesigner: a reaction changed by hand needs them removed.

In every CellDesigner file: the room for a complex's name, which CellDesigner writes at the bottom inside the complex: its members move up, as far as the space above them allows, and the complex grows down for the rest. Multimers are drawn as dimers at the size of the input map, as in SBGN, a count above 2 being the unit of information N:3, N:4 on the node, so a tetramer does not grow and reach its neighbours.

Loading

Updated: 19 October 2026, Pyodide 0.26.4.

Size: about 7 MB compressed (about 20 MB unpacked), downloaded on the first visit, then taken from the browser cache. Almost all of it is Python running in the browser (Pyodide): the Python engine 3.0 MB, its standard library 2.3 MB and the XML library lxml 1.4 MB. The converter itself is 0.06 MB.

Time: estimated 3 to 5 seconds on the first visit over a fast connection, about 10 seconds over a slow one (10 Mbit/s). Later visits need only the start of Python, 1 to 4 seconds. Loading starts as soon as the page opens. Once Python runs, a conversion takes a moment.
